## 🏛️ 1. فلسفة وهندسة المنظومة

نظام **Sirafi Tickets** ليس مجرد منصة لحجز أو بيع التذاكر؛ إنه **منظومة تشغيل متكاملة** تجمع بين إدارة العمليات المالية، تدفق الزوار، التحقق الآمن عبر الرموز التفاعلية، السلامة الأسرية، ومراقبة الضغط الميداني اللحظي.

```
                      🏞️ SIRAFI PARK PLATFORM
                                 │
            ┌────────────────────┴────────────────────┐
            │                                         │
    ☁️ CORE CLOUD ENGINE                   🖥️ ADMIN & OPERATIONS
            │                                         │
  ┌─────────┼─────────┐                     ┌─────────┼─────────┐
 🎟️        🪙        🛡️                    📊        👥        🔄
Tickets   Units    Safety                Analytics  Staff    Ledger & Sync
  │         │         │                     │         │         │
  └─────────┼─────────┘                     └─────────┼─────────┘
            │                                         │
            └────────────────────┬────────────────────┘
                                 │
                   📱 ZERO-HARDWARE INTERFACES
              Visitor Phone  •  Staff Phone / POS
                                 │
                     ⚡ SECURE QR TRANSACTION ENGINE
                                 │
                 ┌───────────────┴───────────────┐
                 │                               │
          🟢 Online Mode                  🟠 Offline Mode
          (Server Source of Truth)        (HMAC-Signed & Nonce Ledgers)
                 │                               │
                 └───────────────┬───────────────┘
                                 │
                       🔄 Idempotent Sync Queue
```

### المبادئ الصارمة للتشغيل:
1. **📱 الهاتف أولاً (Mobile-First):** هاتف الزائر يمثل تذكرته ومحفظته، وهاتف الموظف يمثل قارئ البوابة ونقطة التحقق وغرفة المراقبة.
2. **🚫 لا أجهزة إضافية (Zero Dedicated Hardware):** لا حاجة لبوابات ميكانيكية خاصة، قارئات ليزر، بطاقات RFID ممغنطة، أو أساور إلكترونية مكلفة.
3. **⚡ سرعة فائقة في الميدان:** مدة التحقق من التذكرة لا تتجاوز **100 إلى 200 ملي ثانية**.
4. **🛡️ الخصوصية والأمان:** عدم الاعتماد على التتبع الجغرافي المزعج (GPS)، بل الاعتماد على **سجل آخر نشاط مسجل (Last Recorded Activity Ledger)** عند استخدام الألعاب.

## 🔄 2. نموذج التشغيل الهجين (Hybrid Architecture)

يتيح النظام العمل بثلاث قنوات مرنة متزامنة تضمن عدم إقصاء أي فئة من الزوار:

| فئة الزائر | آلية الدخول والمعاملة | الربط السحابي | التذاكر |
| :--- | :--- | :---: | :--- |
| **🟢 زائر مسجل بالكامل** | رقم الهاتف + هوية زائر فريدة (`V-123765`) + محفظة وحدات عائلية | سحابي كامل | رقمية في التطبيق أو ورقية مرتبطة بالحساب |
| **🟡 زائر سريع (تطبيق بدون إلزام)** | استخدام التطبيق للاطلاع على الخريطة وشراء التذاكر السريعة دون ملف شخصي معقد | مؤقت محلي | تذاكر رقمية موقعة محلياً |
| **🔵 زائر تقليدي (غير مسجل)** | الدفع النقدي المباشر لدى الكاشير بدون أي تطبيق | سجل مجهول (`Anonymous`) | تذاكر ورقية باركود/QR سريعة مطبوعة من الكاشير |

## 🪙 3. نظام الوحدات والمحاسبة الثلاثية (Tri-Ledger Accounting)

يفصل النظام تماماً بين العمليات النقدية وحركات الألعاب لمنع أي تلاعب وتسهيل التدقيق المحاسبي الصارم:

```
[ الزائر يدفع 100 ر.س نقد/بطاقة ]
                │
                ▼
      💰 1. Payment Ledger (سجل المدفوعات المالية)
                │
                ▼
      🪙 2. Unit Ledger (+500 Units رصيد وحدات داخلي)
                │
                ▼
      🎟️ 3. Ticket Ledger (-100 Units ➔ +20 تذكرة دخول/ألعاب)
```

- **الوحدات (Park Units):** رصيد داخلي خاص بالحديقة يُستخدم لشراء تذاكر الدخول، تذاكر الألعاب، أو الاستهلاك المباشر للألعاب عبر مسح سريع (Direct Unit Ride).
- **التذاكر الورقية المرتبطة (Linked Paper Tickets):** عندما يطلب الزائر تذاكر ورقية من الكاشير، تصبح التذكرة الورقية مجرد تمثيل فيزيائي للتذكرة الرقمية في حسابه السحابي.
- **التذاكر مسبقة الطباعة (Pre-printed Range):** يمكن للكاشير ربط نطاق تذاكر جاهز (مثل: `T-001` إلى `T-020`) بحساب الزائر في ثانية واحدة بدون إعادة طباعة.

## 🔐 4. هندسة الرموز المشفرة (QR Engine & Security Architecture)

كل رمز QR يتم توليده في المنظومة يحمل تركيبة مشفرة وفريدة، ولا يمثل مجرد رقم ثابت، مما يمنع نهائياً اختراقات النسخ أو التكرار.

```json
{
  "ticketId": "T-100293",
  "visitorId": "V-123765",
  "type": "USAGE_QR",
  "nonce": "a8f3b2c9-d8e7-4b1a-9f0e-3c7b8a1e2d3f",
  "timestamp": 1724950400000,
  "signature": "hmac_sha256_hash_digest_here..."
}
```

### أنواع الرموز التفاعلية:
1. **`Purchase QR` (رمز الشراء):** يعرضه الزائر للكاشير لخصم الوحدات وإصدار التذاكر.
2. **`Transfer QR` (رمز النقل بدون إنترنت):** يرسل التذاكر مباشرة من هاتف الموظف إلى هاتف الزائر محلياً.
3. **`Entry QR` (رمز بوابة الدخول):** لدخول الحديقة الرئيسية.
4. **`Usage QR` (رمز ركوب اللعبة):** يُمسح من قِبل مشغل اللعبة لاستهلاك التذكرة.

### دورة حياة حالة التذكرة (Ticket State Machine):
```
[ ISSUED ] ➔ [ AVAILABLE ] ➔ [ RESERVED ] ➔ [ VALIDATED ] ➔ [ CONSUMED ]
                                                     │
                                            [ CANCELLED / EXPIRED ]
```

### الحماية من هجمات التكرار (Anti-Replay & Double Spend Mitigation):
- كل QR مزود بـ **معرف فريد غير قابل للتكرار (Nonce)**.
- الرموز مؤقتة الصلاحية وتنتهي تلقائياً خلال دقائق معدودة.
- يتم حفظ الـ Nonces المستهلكة في جدول محلي وسحابي؛ وأي محاولة لتصوير الشاشة أو إعادة إرسال الكود السابق تُرفض فوراً مع إطلاق تنبيه أمني صوتي ومرئي.

## 📵 5. محرك العمل بدون إنترنت والمزامنة (Offline & Sync Engine)

في حال انقطاع تغطية الإنترنت في أي جزء من الحديقة، ينتقل التطبيق **تلقائياً وبشكل غير مرئي (Transparent Fallback)** إلى نمط التحقق المحلي:

1. **مخزون التذاكر المسبق للموظف (Offline Inventory):** يحصل الموظف عند بدء ورديته على رصيد تذاكر مصرح به محلياً (مثلاً: 1000 تذكرة) يقل تلقائياً مع كل عملية.
2. **التحقق بالمفاتيح المشفرة (Local HMAC Verification):** التحقق من صحة التذكرة وتوقيعها الرقمي محلياً دون الرجوع للسيرفر.
3. **طابور المزامنة التراكمي (Sync Queue):** تخزين كافة العمليات محلياً مع تشفيرها.
4. **معالجة التعارض وتكرار العمليات (Idempotent Sync):** عند استعادة الاتصال، تُرسل العمليات دفعة واحدة للسيرفر؛ وإذا أُرسلت نفس العملية مرتين بفعل تذبذب الشبكة، يضمن النظام عدم خصمها مرتين.

## 🛡️ 6. منظومة السلامة العائلية ورصد الحشود (Family Safety & Crowd Telemetry)

تعد هذه المنظومة من أبرز ركائز الحماية الشاملة بالحديقة وتضم عناصر ابتكارية فريدة:

```
[ طفل يستخدم تذكرته في سيارات التصادم 21:03 ]
                     │
                     ▼
       📊 Event Ledger (سجل الأحداث اللحظي)
                     │
         ┌───────────┴───────────┐
         │                       │
 👨‍👩‍👧‍👦 Family Timeline     🗺️ Safety Treasure Map
 (خط زمني لرب الأسرة)    (مؤشر بطارية الضغط اللحظي)
         │                       │
         ▼                       ▼
 🚨 زر الإبلاغ عن مفقود   ❄️ تجميد التذاكر عند الازدحام
         │                       │
         ▼                       ▼
 📢 شريط استنفار أحمر    👮‍♂️ توزيع أفراد السلامة ميدانياً
 (صورة وأوصاف الطفل للجميع)
```

### 1. خريطة الكنز التفاعلية (Safety Treasure Map 🗺️):
لوحة تحكم كنز عتيقة تضم مجسمات وأيقونات مصغرة لجميع ألعاب ومرافق الحديقة مع خطوط الربط ومسارات الحشود.

### 2. مؤشر بطارية الضغط اللحظي (Battery Pressure Gauge 🔋):
بجانب كل لعبة يوجد عمود رأسي يشبه درجات شحن بطارية الهاتف مقسم إلى 5 مستويات:
- **درجة 1-2 (🟢 أخضر):** هادئ وتدفق تذاكر اعتيادي.
- **درجة 3 (🟡 أصفر):** ضغط متوسط ومتابعة مستمرة.
- **درجة 4 (🟠 برتقالي):** ضغط مرتفع وتكدس في صفوف الانتظار.
- **درجة 5 (🔴 أحمر نابض):** ازدحام حرج وتدفق استثنائي يستدعي التدخل الفوري.

### 3. تجميد قطع التذاكر مؤقتاً للسلامة (Ticket Freeze ❄️):
يمكن لضابط الأمن تجميد أي لعبة بنقرة واحدة عند الازدحام الشديد أو الصيانة، مما يعطل إمكانية استهلاك أو شراء تذاكرها فوراً في جميع شاشات الزوار حتى ينخفض الضغط.

### 4. التوجيه الميداني لفريق السلامة (+ / - 👮‍♂️):
توزيع وزيادة أفراد الأمن المتواجدين عند الألعاب الأكثر ازدحاماً بناءً على مؤشرات الضغط الحية.

### 5. شريط نداء استنفار المفقودين على السطح (Public Missing Banner 🚨):
عند إبلاغ ولي الأمر عن طفل مفقود، يرتفع شريط طوارئ أحمر متحرك في أعلى كافة شاشات التطبيق لجميع الزوار والموظفين، يعرض اسم الطفل، عمره، صورته الرمزية، أوصاف ملابسه، وآخر لعبة كان متواجداً عندها وتوقيتها الدقيق.

## 👥 7. أدوار ومسارات التشغيل الميداني (Roles & Portals Breakdown)

يوفر التطبيق 6 شاشات تشغيلية مخصصة لكل دور وظيفي:

```
[ 1. هاتف الزائر 📱 ] ➔ شراء الوحدات، إدارة العائلة، استعراض التذاكر، وركوب الألعاب
[ 2. نقطة الكاشير 🎟️ ] ➔ مسح رموز الشراء، إصدار التذاكر الورقية، وربط التذاكر المطبوعة
[ 3. بوابة الدخول 🚪 ] ➔ مسح سريع لتذاكر الدخول والتحقق الفوري (أونلاين/أوفلاين)
[ 4. مشغل اللعبة 🎡 ] ➔ مسح تذاكر الألعاب وخصم الوحدات المباشر مع رصد طابور الانتظار
[ 5. غرفة الأمن 🚨 ] ➔ خريطة الكنز، مؤشرات البطارية، تجميد الألعاب، والبحث عن المفقودين
[ 6. الإدارة المركزية 🖥️ ] ➔ المحاسبة الثلاثية، التحليلات، إدارة الموظفين، وسجل التدقيق
```

## 🎨 8. تصميم واجهات المستخدم والمؤثرات (Gamified UI, Sound & Themes)

- **انتقالات مراحل الألعاب (Game Stages Transitions):** انتقالات بصرية انسيابية باستخدام `framer-motion` تُشعر الزائر بأنه ينتقل بين مراحل لعبة فيديو ممتعة.
- **أزرار ثلاثية الأبعاد تفاعلية (`btn-game-*`):** أزرار ذات عمق بصري وتأثير ضغط واقعي وألوان مبهجة.
- **محرك مؤثرات صوتية مدمج (Web Audio Synthesizer):** أصوات نجاح النقر، فتح التذاكر، تنبيهات الطوارئ، وتجميد الألعاب تعمل على متصفح الهاتف مباشرة بدون ملفات صوتية ثقيلة.
- **4 ثيمات ألوان متكاملة:**
  - 🏰 **قلعة الحصن والمغامرة (Takeshi Castle):** رمادي ليلي مذهب مع عناصر القلاع العتيقة.
  - 🌿 **الواحة الخضراء (Emerald Oasis):** أخضر زمردي مريح للعين أثناء النهار.
  - 🌊 **نسيم المحيط (Ocean Breeze):** أزرق بحري منعش.
  - 🎡 **الكرنفال الملكي (Royal Carnival):** بنفسجي ملكي ساحر للأجواء الاحتفالية.
- **نظام الأوسمة والإنجازات (Achievements & Confetti):** فتح أوسمة تفاعلية ومكافأة الزوار بوحدات إضافية مع إطلاق قصاصات الاحتفال الملونة.

## 🚀 10. دليل البدء السريع والتشغيل (Quickstart & Setup)

### متطلبات البيئة والتطوير:
- **Node.js:** الإصدار 18 فما فوق.
- **npm / yarn:** متوافق مع كافة أنظمة الحزم الحديثة.
- **المتصفحات المدعومة:** Chrome, Safari, Edge, Firefox على جميع أجهزة iOS و Android و Desktop.

### خطوات التثبيت والتشغيل المحلي:
```bash
# 1. استنساخ المستودع
git clone https://github.com/example/sirafi-tickets.git

# 2. الانتقال لمجلد المشروع
cd sirafi-tickets

# 3. تثبيت الاعتماديات
npm install

# 4. تشغيل خادم التطوير المحلي
npm run dev
```
*يفتح التطبيق تلقائياً على الرابط:* `http://localhost:3000`

### بناء النسخة الإنتاجية (Production Build):
```bash
npm run build
```
